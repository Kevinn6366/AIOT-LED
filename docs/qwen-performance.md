# Qwen 全层 PL 性能实验

使用 ZYBO Z7-20、50 MHz 的 PL 矩阵核、64 位 AXI HP0、同一个 Q4_0 GGUF 和 ARM ELF。两种后端都运行在板上，PC 上的 Edge 负责输入和显示。

## 原位流的分段实测

诊断位流从 `b9ea48d` 的 Vivado 布线检查点生成，保留原核的状态机，使用周期寄存器的低 3 位观察状态。位 0 表示从发起一行权重的 HP0 读取到回到计算阶段；位 1 表示清零累加器、点积、缩放和部分累加；位 2 表示核空闲。最后的行归约、写回、激活读取和其余控制周期单独归入“其他”。权重读取阶段包含有效传输和等待。采样比例是时间占比估计。

板端 SDK 程序在已有的保留 DDR 中运行与模型等尺寸的矩阵，随机化采样间隔。仅覆盖输出暂存区。各行使用实际内核，输入数值不影响这些固定形状循环的分支。空调用测试做 1,000 次参数写入、启动和完成轮询，合计 176,216 个 50 MHz 周期，平均 3.52 微秒。它测量主动轮询的固定开销；应用对大矩阵还会休眠轮询。

| 矩阵（输入宽 × 输出行，列数） | 权重读取 | 算术 | 其他及空闲 |
| --- | ---: | ---: | ---: |
| Q4 查询（896 × 896，2） | 11.57% | 81.00% | 7.43% |
| Q4 FFN 上投影（896 × 4864，2） | 11.61% | 80.95% | 7.43% |
| Q4 FFN 下投影（4864 × 896，1） | 10.34% | 88.03% | 1.63% |
| Q8 词表输出（896 × 151936，1） | 16.43% | 76.56% | 7.01% |
| FP 注意力样本（64 × 64，1） | 22.79% | 47.39% | 29.82% |

同一道灯题从首个到最后一个活跃样本，共 121,933 次采样。算术占 79.35%，读取权重行占 12.22%，核空闲占 2.21%，其余占 6.22%。核空闲含 PS 调度、激活处理和采样，因此 2.21% 不能全部计为调用开销。该次网页首字 161.31 秒、生成 0.09689 token/s，与原位流的两轮记录一致到百分之一以内。[阶段原始计数及同题回包](qwen-phase-samples.json)

复测时在仓库根目录用 Vivado 执行 `hardware/qwen/profile-baseline.tcl`，输入检查点须由原提交生成。用 SDK 的 ARM Linux GCC 以 `-O2 -static` 编译 `tests/qwen_profile.c`。在维护窗口暂停访问 PL 的板端进程，用 FPGA Manager 加载诊断位流。运行采样程序取得上表；恢复应用后，用其 `sample` 模式旁路采样，再运行 `python tests/compare_qwen.py --sample-baseline` 取得整道题的分布。采样器首先校验空闲标志，正式位流的周期寄存器仍使用完整的 32 位计数。

## 修改

原核每次读完一行，再逐块计算，每块分四次取激活。新核按最多 64 行连续读取 DDR，用 FIFO 连接取数、权重拼装和点积。每个块的 32 个整数乘法展开，两列激活使用独立分区，缩放与行累加在流水线中执行。HLS 综合得到取数每周期一字，量化点积的启动间隔为 3 周期。量化格式、时钟、两列接口、PS 调度和纯 PS 对照保持相同。

## 两列流水核的网页结果

固件 `5a91857fe6c1` 在 B 槽启动。Vivado 实现占用 31,033 个 LUT、54 个 BRAM Tile、140 个 DSP；WNS 2.854 ns、WHS 0.016 ns。两轮均算 42 个提示 token、生成 17 个 token，回答完全相同。PL 两轮首字均为 29.33 秒，速度为 0.54286、0.54263 token/s；纯 PS 两轮首字均为 24.29 秒，速度为 1.06088、1.05946 token/s。相较原 PL，首字耗时降至约 18%，生成速度提升至约 5.6 倍。两列版本的首字仍比纯 PS 慢 5.04 秒。[四次网页请求的原始结果](qwen-two-column-comparison.json)

## 四列提示词处理

量化核把同一块 Q4 或 Q8 权重送给四列激活，单列解码和最后一个不足四列的分组共用同一接口。PS 对量化矩阵每次提交最多四列，对浮点注意力仍提交最多两列。输出按行写入，每两个 FP32 合为一个 64 位字。Vivado HLS 对单列至四列、跨 64 行边界和 4864 维 FFN 做了独立数值比对。

四列版使用 36,678 个 LUT、63 个 BRAM Tile 和 207 个 DSP。50 MHz 下布线后 WNS 为 2.290 ns、WHS 为 0.020 ns。A 槽版本为 `c1417b85fc07`，写入后回读的 FIT SHA-256 为 `708e5fd20c3e3ed469e634a46d72e798f0cdfcd9e9a4d657dff8a306019abc8e`。重启后的灯控、双 RGB 同步，以及两组 ZyboGPT 续写向量均通过回归。

单请求逐 token 解码时，下一列激活依赖刚生成的 token，无法像提示词一样合并四列。按现有 DDR 格式，24 层量化矩阵和输出头每个解码 token 合计读取 438,538,240 字节。即使 64 位、50 MHz 的 HP0 每周期传一字，光读权重的理论下限也为 1.096 秒/token。这是当前结构的带宽上限估算。

| 第一轮 | 21.90 | 24.67 | 0.49828 | 1.04658 |

题目为“一盏红灯加两盏绿灯，一共有几盏灯？”。四次均重新处理 42 个提示 token，生成相同的 17 个 token。每轮 PL 均有 29,387 次调用，覆盖 24 层、十种矩阵运算；纯 PS 的 PL 调用与周期均为零。两轮平均首字耗时下降 2.79 秒（11.3%），生成速度约为纯 PS 的 47.6%。[四列版完整网页记录](qwen-four-column-comparison.json)

## 紧凑权重与独立 Qwen 时钟

固件 `493e9570ad55` 的矩阵核和 HP0 运行在 125 MHz，GP0 控制、灯控、ZyboGPT 和测量周期用的计数器仍运行在 50 MHz。每四个 Q4_0 或 Q8_0 块以一个 64 位字存放原始 FP16 缩放值。逐 token 读取的权重由 438,538,240 降至 345,920,512 字节。测试覆盖四个缩放值的位置、正负 FP16 次正规数和跨分块输出。Vivado 实现使用 29,782 个 LUT、63 个 BRAM Tile、170 个 DSP，WNS 为 0.212 ns，WHS 为 0.014 ns。

同题两轮，单端口 PL 首字为 13.16、13.18 秒，生成速度为 0.926、0.928 token/s；纯 PS 为 24.71、24.63 秒及 1.041、1.041 token/s。虽然显著快于四列旧固件，生成速度仍低于纯 PS。最后一个解码图中 FFN gate 和 up 的调用窗口分别约 200 毫秒，注意力分数及加权求和各约 57 毫秒。原始数据的 `pl_op_cycles` 是整题按运算分类的 50 MHz 参考周期，`pl_last_graph_cycles` 是最后一个含输出头的图。窗口计入核执行、传输以及 PS 等待完成的时间。[四次网页记录](qwen-compact-comparison.json)

## 双端口并行与注意力合并

三到四列提示词共享一行权重。单列或双列时，把量化输出行平分给 HP0 和 HP2，两个读引擎各自连续取数，左右两对乘加通路各算一组行。这样同时生成两个不同行的结果。PS 在同一个 KV 组内按向量填满两个浮点注意力通路。板上只有一个 Qwen 请求在运行。HP0/HP1 和 HP2/HP3 分别连接两个 DDR 控制器端口。[AMD DDR 控制器连接说明](https://docs.amd.com/r/en-US/ug1145-sdk-system-performance/Evaluating-DDR-Controller-Settings)

本次 A 槽固件 `bdf7ca62b59d` 的 Qwen 时钟为 110 MHz，使用 33,832 个 LUT、72 个 BRAM Tile 和 215 个 DSP。125 MHz 初次布线未满足建立时间。用对应 110 MHz Clocking Wizard 的两项 MMCM 参数重用同一布线，并核对生成时钟、保持时间、硬件描述中的 BIT。最终 WNS 0.467 ns、WHS 0.010 ns。重建此物理变体时，用 `AIOT_QWEN_ROUTE_125=1` 运行本提交的 BD 脚本保留原布线，然后清除此变量，生成 110 MHz 工程的硬件描述，再在 Vivado 中执行 `hardware/qwen/reclock-dual.tcl`。只导出通过时序的位流。

两轮 PL 首字分别为 9.82、9.83 秒；速度为 1.864、1.863 token/s。两轮 PS 首字均为 24.82 秒；速度为 1.040、1.040 token/s。回答一致，PL 的 24 层和十类运算都有回读。最后一个解码图的词表输出由约 258 毫秒降到 96 毫秒，FFN gate、up 分别由约 200 毫秒降到 73 毫秒。[双端口原始网页记录](qwen-dual-comparison.json)
